# Ansible Subsystem

## Overview

Ansible playbooks run **exclusively inside a dedicated Podman container** (`sentry-ansible`), never on the host. This container is built from `Dockerfile.ansible` and includes the `cisco.ios` collection with legacy SSH cipher support for older Cisco devices.

## sentry-ansible container

**Built via:** `python watchman/scripts/container_manager.py build`
**Image:** `localhost/sentry-ansible`

### Key characteristics

- Contains the `cisco.ios` Ansible collection
- Legacy SSH ciphers enabled: `diffie-hellman-group1-sha1`, `ssh-rsa`
- `host_key_checking = False` in `ansible.cfg`
- Playbook directory mounted at `/ansible` inside the container
- `--network=host` mode for SSH access to lab devices
- `--pull=never` — image must exist locally, never pulled from registry

### Container lifecycle

Managed by `watchman/app/services/execution_service.py`:
- `get_podman_command()` (`:18-30`) — builds the podman run command
- `_run_podman()` (`:50-57`) — executes with 300s timeout
- `run_playbook_stream_generator()` (`:75-96`) — SSE streaming variant
- `_build_podman_command()` (`:33-47`) — generic command builder for scripts

## Playbook catalog

**File:** `watchman/playbooks/catalog.json` (475 lines, 19 entries)

Each entry has:
- `filename` — `.yml` file name
- `name` — human-readable name
- `description` — one-line purpose
- `tags` — keyword array for suggestion matching
- `target_devices` — inventory group names (e.g., `["allHosts"]`, `["Edge_routers"]`)
- `example_intents` — NL examples for suggestion engine
- `destructive` — boolean flag for staging gate
- `severity` — `"low"`, `"medium"`, `"high"`, `"critical"`

## Inventory

**File:** `watchman/playbooks/hosts.ini`

Generated by the setup wizard or manually edited. Sections:
- `[allHosts]` — every device
- `[Edge_routers]` — edge/WAN routers
- `[Core_Switches]` — core switches
- `[Distribution_Switches]` — distribution switches
- `[HSRP_Routers]` — HSRP-paired distribution switches
- `[Access_Switches]` — access switches (with vlan_id, vlan_name, defaultGateway vars)
- `[allHosts:vars]` — global credentials and connection settings

### Vars section always includes:

```ini
[allHosts:vars]
ansible_network_os=cisco.ios.ios
ansible_connection=network_cli
ansible_user=admin
ansible_password=cisco
ansible_become=yes
ansible_become_method=enable
```

## Quirks & limitations

- **SSH legacy ciphers:** Required for older IOS devices; configured in the container's `/etc/ssh/ssh_config`
- **host_key_checking=False:** Disabled in `ansible.cfg` — not production-safe
- **`--pull=never`:** If the `sentry-ansible` image is missing, playbook execution fails silently
- **300s timeout:** Long playbooks (e.g., `goldenState.yml` on many devices) may time out
- **No sudo in container:** The container runs playbooks as the container user, not root
- **Output not persisted:** `--rm` flag removes container after each run; output captured in API response only
- **Script mounts:** `run_drift_analysis()` and `run_baseline_refresh()` mount the `scripts/` directory at `/scripts` inside the container (`execution_service.py:41-44`)
